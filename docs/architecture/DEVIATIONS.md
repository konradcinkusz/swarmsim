# Open deviations

Per [`00-REFERENCE-ARCHITECTURE.md` §3a](https://github.com/konradcinkusz/architecture-standards/blob/main/docs/architecture/00-REFERENCE-ARCHITECTURE.md#3a-known-open-deviations):
an unacknowledged gap from the constitution is drift; an acknowledged one is a decision.
This table is that acknowledgment. When a row is fixed, it is deleted, not marked done.
A row whose trigger has fired says so — a fired trigger nobody acted on is the same
drift this register exists to prevent, just with better paperwork.

| Principle | Deviation | Since | Reasoning / trigger to close |
|---|---|---|---|
| P1 (AppHost is the composition root) | No .NET Aspire AppHost. `SwarmApi.Api` is a single ASP.NET Core project; the development composition root is `docker/docker-compose.yml`, which now orders startup with a healthcheck (`api` waits for rosbridge). | M3 | See [ADR-0002](../adr/0002-composition-root-split.md). Trigger: a second .NET service of this repo's own (the M5 mission layer was the planned one). The compose file already carries four services, so revisit if startup ordering needs more than one healthcheck edge. |
| P2 (shared kernel) — partly | `SwarmApi.ServiceDefaults` is guarded by an architecture test and a CI size ceiling (2026-09-22), but JWT wiring lives in `SwarmApi.Infrastructure` rather than the kernel, and there is no OpenAPI document. | M3 | One service validates tokens, so the kernel has nobody to share them with yet; an OpenAPI generator would be a second third-party runtime package (see the README's dependency budget). Trigger: a second service validating the same tokens, or the first consumer outside this repository needing a machine-readable contract. |
| P5 (JWT / asymmetric signing), narrowed | `SwarmApi.Api` supports JWT bearer auth (RS256, JWKS) against an external `authservice` instance, but only gates `POST /api/missions`; `GET` endpoints and the dashboard stay open even when Enforced, and the dashboard has no login UI. Tokens carry no tenant claim yet. | M3; narrowed 2026-09-21 | See [ADR-0005](../adr/0005-mcp-server-and-bearer-auth.md). The write an MCP-driven Agent invokes is attributable; reads, the dashboard, and per-tenant identity are not yet. Trigger: a login flow for the dashboard, a requirement to distinguish *readers*, or per-tenant token claims (needed by [ADR-0006](../adr/0006-multi-tenant-isolation-model.md)'s orchestrator). |
| P7 (Fly.io) — `swarmsim-api` | No `fly.toml` for the API and scenario path. | M3 | Target decided in [ADR-0007](../adr/0007-deployment-target.md): a cheap, scale-to-zero Fly app. **Trigger fired 2026-09-21** — ADR-0007 made this unit's trigger "issue #12's scenario library lands", and it has. Not yet actioned: the scenario library still runs only in-process in Python, so there is nothing hosted to demo. Close by deploying, or re-date the trigger with a reason. |
| P7 (Fly.io) — `swarmsim-sim` | No deployment path for the Gazebo/PX4/ROS 2 stack. | M3 | Per ADR-0007 and ADR-0006: per-tenant, per-run instances, never a standing deployment. Trigger: first pilot with a real operator, and the ADR-0006 orchestrator existing. |
| P8 (visible degradation) — after startup | `RosBridgeSwarmBridge` picks Connected once, never reconnects, and after a dropped connection `GET /health` keeps reporting `Connected` while state goes stale. In Connected mode the API also reports status `InFlight`, battery 100 % and no active mission for every drone — values nobody measured. | M3 | The startup half of P8 is met ([ADR-0003](../adr/0003-rosbridge-degrade-pattern.md) and its 2026-09-22 amendment); the after-startup half is not. Trigger: already due — the bridge needs reconnection, live connection state in `/health`, and telemetry that says "unknown" instead of inventing a value. |
| P12 (tag-driven CI/CD, change detection, ordered deploy) | CI builds and tests on every push/PR; `release.yml` creates a GitHub Release from a `v*` tag; there is no deploy job and no tag has been cut. | M3 | Follows from the P7 rows — nothing to deploy to yet. Trigger: same as P7 `swarmsim-api`. |
| P13 / TESTING-STRATEGY §9 — simulation layer | Nothing in CI builds `docker/Dockerfile.sim` or runs PX4 SITL, so M0/M1 ("a drone spawns and takes off") and M3 against the real stack are verified by no automated context. CI checks the compose file, the world file, the drone configs' presence and the entrypoint's logic against stubs. | M0 | See [ADR-0004](../adr/0004-ci-scope-for-simulation-stack.md). The drone configs were missing from the repository until 2026-09-22 and the image build ran the simulator instead of compiling it, which is what "verified by no automated context" costs. Trigger: already due — a headless, CPU-only SITL smoke job. |
| P13 (E2E layer / Playwright) | No end-to-end browser suite. The dashboard has one interactive flow — **Start demo mission** posts `/api/missions` — covered at the API layer by `MissionsEndpointTests`, and in the browser only manually. | M4 | The row used to call the dashboard read-only; it never was. One button over an API that is tested directly is still cost without signal for a browser suite (TESTING-STRATEGY.md §1). Trigger: a second interactive flow, or any flow the API tests cannot reach (a login or an approval step). |
| P15 (OTLP observability) | No OpenTelemetry exporter wired. `SwarmApi.ServiceDefaults` exposes `/health` and `/alive` only. | M3 | No collector endpoint exists to export to yet, and P8's "visible degradation" is met at startup by the `/health` payload naming the bridge and auth modes. Trigger: first deployed environment with an OTLP collector. |
| P3 / P4 (service owns its database, `MigrateAsync`) | `SwarmApi.Api` is stateless; swarm state lives in memory (real: rosbridge-fed; fallback: simulated engine) and missions are not persisted across restarts. | M3 | Outside the rule, not an exception to it (constitution P4 note): there is no entity model and no schema to migrate. Trigger: a requirement to recall a mission or a scenario run after a restart. |

Everything not listed here is met as stated in `docs/architecture/README.md`'s
compliance checklist.
